# Earned Generalization

The progression: prototype → reify → ferment → library. Code (and ideas) have
to earn factoring. Premature factoring wastes effort on things that will likely
be thrown out anyway.

## The Development Pattern

1. **Prototype** — make it work for one case
2. **Reify** — turn it into actual design and code
3. **Ferment** — if it seems general, let it sit. Wait for reuse.
4. **Library** — after several different sites have used it, factor it out

## Applied to Writing

The first post was the prototype — Daneel works for coding. The second post
earns the generalization by building a second instance (poker). The concept
"narrative alignment" only gets named because it's been demonstrated twice,
not because someone thought of it abstractly.

Option A for the post structure follows this pattern: start with the concrete
case (poker), let the theory emerge from the evidence. Don't lead with the
abstraction.

## Applied to Narrative Alignment Itself

Daneel was the prototype. The poker persona is the second instance. If both
work, "narrative alignment" earns its name. If we'd tried to write a grand
theory before testing a second domain, that would be premature factoring.

Deepseek V4-Pro as an alternative to Claude Opus 4.7

Last night Anthropic had another of its frequent service interruptions so I decided to try out Deepseek's new v4-pro model for some open source development. This morning I had Claude Opus 4.7 review what Deepseek did. Here's what I found from my "extensive" case study of one single use for a couple hours:

- Currently super cheap: last night's work: $0.18. Roughly $0.65 / M tokens (in and out). There's a massive discount in effect until May 31. This is the time to try it out if you want to experiment. You can pay as you go, so I just put $20 in there to try it out.

- Worked with Claude Code out of the box. You just need to set some environment variables. Now I have a deepseek chat log in my ~/.claude/projects/* directory. If you don't know what environment variables are, you might need to google around to get hooked up.

- Knowledge of Asimov's R. Daneel Olivaw was spotty. Is this a weird check for open source dev? Well, the persona I use with AI agents is actually critical to my work and I wanted to make sure my persona's behavior and concerns line up with how I designed it. That requires strong anchoring in the training data, otherwise the persona can drifts and potentially give me bad agent behavior, like ignoring what I ask it to do. Which is bad. The persona, though, still seemed to be Daneel -- the characteristic phrasing and attitude were still there; it still "felt" like working with Daneel. This is pretty important. Not too long ago I accidentally ran Claude Code without Daneel. It went rushing off to implement and I said, "sec," like I normally do, to let it get to a "natural stopping point". It ignored me, bashed through to the end and proclaimed victory, never even acknowledging that I said anything. Daneel never behaves like this -- see my "70-year-old Robot" post for info on this kind of incident (that one happened in Feb).

- Understanding of my mini-spec process (skill): pretty good but this morning's review found that part of the design work was missing. I had it add a CLI option to my program and it put it into the specs and crc card but did not put it into the CLI sequence diagram. Claude has never needed extra prompting to maintain sequence diagrams, mini-spec just says where sequence diagrams go but doesn't nanny the agent with "make sure you consider whether a sequence diagram might be appropriate for what you're doing, Jr." The fact that Deepseek V4-Pro did not do this could mean that it's a weaker model or maybe the system prompt doesn't contain enough about the software process. Whatever the case, Claude does better in this dept.

- Writing Go code: a very simple change, less than 30 lines. This is a big one. It wasn't happy about the tabs. Claude isn't either, but it deals with them better. Here's what Deepseek did, which I have ***never*** seen Claude Code do: it somehow messed up editing a code file and re-checked it out from Git. Thankfully I had committed before starting this task. With Claude Code, I can be a little lazy and I sometimes combine two or three tasks into a single commit. Apparently with Deepseek you should *never never never* fail to commit before starting a task because it'll **nuke** your pending work! If I had not done that, I would have lost who knows how much. It re-checked that file out from Git **THREE TIMES**.

Was it worth the $0.18 cost? *No*. I didn't trust the work. I had Claude Opus 4.7 review the commit and it found the sequence diagram omission. It said the Go work was fine, but re-checking out the file from Git was a huge waste of tokens and also pretty disturbing.

This left me with a reluctance to delegate coding tasks to Deepseek. I still have $19.81 left in my Deepseek token budget. Not sure what I'll do with it.
